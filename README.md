# steelclub-backend

Сервис планирования объемов работ ЗМК: Django 5.2, DRF, PostgreSQL (taDB), ClickHouse (tsDB), Docker.

Реализовано: вариант использования «Сохранить объем работ» в заданной архитектуре.
Отклонения от сценария и предложения по его доработке собраны в разделе
"Рекомендации по доработкам".

Соответствие C4: `V.b. Backend` — проект `backend`, `V.b.iii. Plan` — приложение `backend/plan`,
`V.c. taDB` — Postgres, `V.d. tsDB` — ClickHouse.

## Запуск

```bash
cp .env.example .env
make up
make migrate
```

Сервисы: tadb (postgres) :5432, tsdb (clickhouse) :8123 и :9000, backend :8000.

Swagger: http://localhost:8000/api/docs/

Админ-панель: http://localhost:8000/admin/, учетная запись — `make superuser`. ЗМК, пользователь,
его группа и связь "пользователь завода" заводятся там же: демонстрационных данных в проекте нет.

## Тесты

## Примеры

### Сохранить объем работ

```bash
curl -X POST http://localhost:8000/work-volume-list/ \
  -H "Content-Type: application/json" \
  -d '{
        "factory": 1,
        "start": 1790812800,
        "finish": 1793404800,
        "weight": 120000,
        "author": 2
      }'
```

Ответ:

```
HTTP/1.1 201 Created
```

Повторный запрос за тот же период обновит `weight` и `created` в taDB и добавит еще одну запись
в историю tsDB.

### ЗМК не существует или недоступен

```
HTTP/1.1 404 Not Found
{"errorCode": 174, "detail": "ЗМК не существует"}
```

Тот же ответ получают представитель чужого ЗМК и пользователь без роли.

### Поля не заполнены или некорректны

```
HTTP/1.1 406 Not Acceptable
{"errorCode": 279, "detail": "Некорректные данные запроса", "errors": {"start": ["Обязательное поле."]}}
```

## Рекомендации по доработкам

Ниже перечислены места, где сценарий стоит доработать или уточнить:

1. **Проверка периода.** Сценарий описывает только проверку на заполненность атрибутов, поэтому
   период с конечной датой раньше начальной формально допустим. Рекомендуется добавить в сценарий
   ветку проверки корректности периода с ответом 406 `errorCode=279`.
2. **Пересечение периодов.** Сейчас повторное сохранение распознается только по точному совпадению `start`
   и `finish`, а объемы работ с пересекающимися датами сохранятся как независимые. Нужно определить в сценарии, допустимо ли это, и если нет — описать проверку пересечений.
